# 大模型 / 多模态面试笔记（定稿）

**文档性质**：面向 AI 应用 / Agent / RAG / 多模态岗位的**口述级**总纲，合并自 `互联网AI转型技术准备等22个文件` 中与 LLM、RAG、Agent、VLM 相关的专题笔记，并补上面试串联题与自检清单。  
**使用建议**：每一节先背「30 秒版」，再审「扩展 bullet」；现场按面试官深度切换到 2～5 分钟版。

## 〇、一分钟总述（开场可用）

大模型侧本质是 **Transformer 基础上的规模化预训练 + 对齐**；应用侧主流范式是 **RAG 补知识与可追溯**、**Agent 做多步任务与工具闭环**、**VLM 把图像变成 LLM 可用的视觉 token**。BERT 系擅长 **理解与向量检索**，GPT 系擅长 **自回归生成**；多模态里 **CLIP 解决图文对齐**，**LLaVA / Qwen-VL 一类解决看图说话与推理**，**Grounding DINO + SAM** 常见组合解决 **开放词汇定位与精细分割**。工程上要能讲清 **延迟、成本、容错、评测与安全**。

## 一、Transformer 与 Attention

### 30 秒版

Transformer 用 **Self-Attention** 让任意两个 token 直接交互，**并行训练**，擅长长距离依赖；核心是 **Q/K/V → scaled dot-product softmax → 加权 V**。Decoder-only（GPT 类）加 **Causal Mask**，Encoder-only（BERT 类）双向看上下文。主要代价是序列长度 **\(O(n^2)\)** 的注意力开销。

### 必背要点

- **Self-Attention**：每个位置的输出 = 对全序列 Value 的加权，权重由 Q 与 K 的相似度经 softmax 得到。
- **为什么要除以 \(\sqrt{d_k}\)**：点积随维度放大，softmax 饱和、梯度变小；缩放稳定训练。
- **Multi-Head**：多组 QKV 子空间并行，捕捉不同类型依赖（语法、指代、远程等）。
- **位置信息**：Attention 本身无序；需 **Token Embedding + Position Embedding**，常见 **可学习 / 正弦 / RoPE / ALiBi**。
- ** Encoder-only / Decoder-only / Encoder–Decoder **：理解 vs 自回归生成 vs -seq2seq（翻译、T5 类）。
- **Cross-Attention**：Q 来自一端，K/V 来自另一端；用于 decoder 看 encoder，或 **文本 query 看图像特征**。
- **FFN**：逐 token 的非线性变换；大模型里参数占比常很高。
- **Pre-LN vs Post-LN**：现代大模型多用 Pre-LN，深层训练更稳定。

### 常见追问

| 问题 | 答法要点 |
|------|-----------|
| 相对 RNN/CNN | 并行；全局依赖；归纳偏置弱、更吃数据；长序列成本高 |
| 复杂度 | 时间/显存约 \(O(n^2 d)\)；FlashAttention、稀疏/线性 Attention、KV Cache 缓解推理与显存 |
| 与多模态关系 | 图像切块/特征当 token；跨模态时用 Cross-Attention 或先对齐再进 LLM |

## 二、BERT 与 GPT（及对齐）

### 对比（必考）

| 维度 | BERT（Encoder） | GPT（Decoder） |
|------|-----------------|----------------|
| 注意力 | 双向 | Causal / 单向 |
| 训练目标 | MLM（+NSP）等 | 下一个 token 预测 |
| 强项 | 分类、匹配、NER、**检索向量化** | 生成、对话、**Agent**、工具调用 |
| 生成 | 不自然 | 自然 |

### SFT / RLHF / DPO（一句版）

- **SFT**：指令数据监督微调，学会「跟 prompt 走」。
- **RLHF**：奖励模型 + PPO 等，把输出推向人类偏好（流程重、调参难）。
- **DPO**：直接用 chosen/rejected 偏好对优化策略，**省去显式 RM + PPO**，工程上更省事。

### 幻觉（简答）

自回归目标是最可能续写，不是「保证真」；缓解：**RAG、引用、约束只依据上下文、工具与外部 API、拒答、事实校验、人在回路**。

### 在 RAG 里的分工

- **Embedding / 重排**：常 BERT 系、E5/BGE 等双塔表征。
- **最终答案**：GPT 类读检索上下文生成。

## 三、Tokenizer、词表与 Embedding

### 关系链

**文本 → Tokenizer → token → id → Embedding 矩阵行向量 → Transformer**。

### 子词算法（认得即可）

**BPE**（GPT/RoBERTa）、**WordPiece**（BERT）、**SentencePiece**（可先分词无关 UTF-8 流）；平衡 **词表大小、序列长度、OOV**。

### Embedding

- \(V \times d\) 可训练表；语义相近 token 在训练中被拉近了比 one-hot。
- **Weight Tying**：输入 embedding 与输出层共享，减参、稳训练。
- **与位置编码**：相加或 RoPE 等融合方式。

## 四、RAG（检索增强生成）

### 30 秒版

RAG = **Retriever + LLM**：把外部知识入库检索，再将 **Top-k chunk** 与用户问题一并给模型生成，用于 **私有化知识、可追溯、减轻幻觉与知识过期**。关键在 **切块、embedding、检索、（可选）重排、prompt 约束**。

### 流程（背链路）

文档 → **Chunk** → **向量化** → 向量库 → 用户 Query 向量化 → **召回 Top-k** → **Rerank Top-n** → 拼上下文 → LLM → 答案（+引用）。

### 工程要点（面试官爱听）

- **Chunk**：过大噪声多占位；过小语义碎；**递归切分**（标题→段→句）、**overlap**；表格/代码单独策略。
- **Embedding 选型**：语种、领域、维度、召回评测（Recall@k、nDCG）、延迟与成本。
- **向量检索**：余弦/内积；大规模 **ANN（HNSW、IVF+PQ）**；常 **Hybrid：Dense + BM25** 补专有名词。
- **Rerank**：交叉编码器打分 query–doc；或与 LLM 打分；解决「向量像但不答问题」。
- **为何召回后还要 Rerank**：向量是压缩语义，细节（否定、数值、实体）易丢。
- **RAG vs 微调**：RAG 适合**可变知识库**；微调适合 **风格、格式、行为**；常组合。

### 评测口径（说出口）

上下文命中率、答案忠实度（是否违背引用）、端到端准确率、延迟、单次 token 成本、人工抽检 bad case。

## 五、Function Calling 与 Agent

### Function Calling（30 秒）

模型 **只产出结构化调用意图**（函数名 + 参数）；**执行与副作用**在业务侧。价值：**实时数据、精确计算、操作系统的工具化、schema 约束输出**。要点：**描述清晰、工具少而精、JSON Schema 校验、超时重试、权限与审计**。

### Agent（30 秒）

在 LLM 之上增加 **规划、工具循环、记忆、状态机**：「Thought → Action → Observation」反复直到满足停止条件。**RAG 可被视为 Agent 的一个工具**。

### 与 RAG 区别

| | RAG | Agent |
|---|-----|-------|
| 目标 | 补知识作答 | **完成任务** |
| 流程 | 检索→生成 | 规划→调用→观察→迭代 |
| 多步 | 一般单段式为主 | **常多步** |

### 不稳定与安全（必提）

死循环：**最大步数/工具次数/超时/成本预算**。  
上下文爆炸：**摘要、仅存关键状态、向量记忆**。  
安全：**Prompt 注入、越权调用、高危操作二次确认、沙箱、日志**。

## 六、多模态主干（按面试优先级）

### 6.1 CLIP

- **是什么**：图文 **对比学习**，双编码器映射到同一空间，匹配对近、非匹配远。
- **零样本分类**：类别写成 prompt（如 “a photo of a dog”），与图像算相似度取 argmax。
- **强项 / 短板**：开放语义、检索强；细粒度计数/空间/OCR/推理弱；受 **prompt 与数据偏差**影响。
- **和 VLM**：CLIP ViT 常作 **视觉骨干**。

### 6.2 BLIP / BLIP-2

- **BLIP**：MED 结构；**ITC**（对比，近 CLIP）+ **ITM**（ matched 二分类）+ **LM**（caption/VQA）；**CapFilt** 自举洗数据。
- **BLIP-2**：**冻结 ViT + Q-Former + 冻结 LLM**，强调「如何把视觉接到 LLM」。

### 6.3 LLaVA

- **结构**：**Vision Encoder（常 CLIP） + Projector + LLM**。
- **Projector**：把视觉特征对齐到 LLM token 空间（Linear/MLP/Q-Former 系）。
- **训练两阶段**：先 **图文对齐**（常冻视觉与 LLM，训投影）；再 **多模态指令微调**（投影+部分/全 LLM）。
- **幻觉**：仍由 LLM 生成；可用更强视觉、提高分辨率、OCR/检测工具、grounding 数据、约束「只述图中可见」等缓解。

### 6.4 Qwen-VL（代表国产 VLM 叙事）

- **结构**：Vision Encoder + **Adapter/Projector** + **Qwen**。
- **相对 LLaVA 常强调**：中文、**OCR**、**Grounding 坐标**、对话版（如 *-Chat）指令跟随。
- **训练叙事**：多模态预训练（对齐）→ 指令微调（会用）→ 偏好/安全对齐（答得好）。

### 6.5 SAM

- **结构**：**Image Encoder（ViT） + Prompt Encoder + Mask Decoder**。
- **提示**：点/框/mask；**一次多点可能多 mask**（消歧）。
- **定位**：通用 **可提示分割**，**不自带类别**；常与检测/CLIP 组合认类。

### 6.6 Grounding DINO 与「检测版 DINO」

- **Grounding DINO**：**开放词汇检测**；图+文本 prompt → **bbox**；跨模态融合 + 语言引导 query；常与 **SAM** 组成 **文本找框 → 精细 mask**。
- **DINO（检测）**：DETR 路线改进：**去噪训练 DN**、anchor 式 query、对比去噪等，**收敛快、精度高**。
- **DINO（自监督）**：另一概念 *self-distillation ViT*，面试先 **厘清语境**。

### 6.7 VLM 与传统 CV

| | 传统检测/分割 | VLM |
|---|----------------|-----|
| 输出 | 框/mask/类别 | **自然语言、推理、对话** |
| 数据 | 大量框/像素标注 | **图文对、指令数据** |
| 优势 | 任务专精 | 开放语义、少样本指令 |
| 风险 | 分布外差 | **幻觉、细粒度不稳** |

## 七、计划中的「串联题」标准答法（精简）

1. **CLIP 为什么能做图文对齐？**  
   大规模图文对 **对比损失**，拉近配对、推远非配对，共享嵌入空间。

2. **LLaVA 怎么把视觉接到 LLM？**  
   视觉骨干提特征 → **Projector** 映到与词向量兼容的序列 → 与文本 token **拼接**进 **Decoder-only LLM**。

3. **VLM 和传统 CV 区别？**  
   见上表；强调 **交互、开放词表、端到端语义**，代价是 **可控性与细粒度**。

4. **多模态 fine-tuning 一般训谁？**  
   常见：**先 Adapter/投影**，再放开 **LLM 部分层**；视觉编码器 **冻或小 LR**；数据含 **QA、OCR、grounding** 等按任务加。

5. **RAG 如何评估？**  
   **检索**：Recall、MRR、nDCG；**生成**：忠实度、引用一致性、人工；**系统**：P99 延迟、成本。

6. **Agent 不稳定怎么办？**  
   规划格式约束、**有限状态**、工具白名单、重试与降级、**最大轮次**、轨迹日志与回放评测。

7. **幻觉如何缓解？**  
   RAG+引用、温度与约束、工具验证、知识边界拒答、人在回路。

8. **多模态如何落地业务？**  
   场景选 **高价值/可评测** 子任务；人机协同；**评测集**与 bad case 回流；成本（GPU/Token）与降级策略。

## 八、两条「现场口述模板」

### 模板 A：让你讲 RAG 架构

「典型是离线索引 + 在线检索。文档先 **切 chunk** 做 **embedding** 入向量库；线上 **query 改写/向量化**，**Dense+BM25 混合召回**，再用 **Cross-Encoder 或 LLM** 重排，取 **Top-n** 放进带 **仅依据上下文、列引用** 的 prompt。监控 **召回命中、答案违背引用率、延迟和 token 成本**，bad case 回流改 chunk 与 embedding。」

### 模板 B：让你讲 Agent

「Agent = **LLM 决策 + 工具执行环境**。用户目标进来后做 **规划**，通过 **Function Calling** 调搜索/库/SQL/代码解释器等；每步 **Observation** 回灌，**状态机**记计划与中间结果，设 **步数与预算** 防死循环。安全上 **鉴权、参数校验、敏感操作确认、全链路日志**。」
