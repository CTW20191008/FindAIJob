## 1. 背景与目标

### 1.1 要解决什么问题

- **复习与口述**：把你的 Markdown 知识体系（面试笔记、RAG/多模态方案）转成可对话的记忆辅助，而非翻长文。  
- **求职闭环**：在同一路径内完成 **履历要点问答 → 与 JD 对照 → 面试题演练**，减少多工具跳转。  
- **证据可追溯**：答案应绑定 **出处片段**，与《RAG 系统设计》中「可追溯、拒答」原则一致。

### 1.2 成功标准（MVP）

| 维度 | MVP 达标线 |
|------|------------|
| 知识覆盖 | 对仓库内已定稿 Markdown **可检索、可问答**，并能 **标注来源文件名/章节或 chunk ID** |
| 忠实度 | 对「文档未写明」的问题 **明确拒答**，不编造项目经历 |
| 体验 | 单轮问答端到端可接受（本地或小流量；具体秒级在实现阶段定靶） |
| 可演示 | **Web 单页 + README** 说清语料路径、**多厂商模型切换**、公网部署注意事项 |

## 2. 部署形态、用户与隐私（已确认：公网）

### 2.1 部署结论

- **公网可访问**：服务暴露在公网时，**默认视为不可信网络**；必须配套 **HTTPS、鉴权、限流** 与 **最小暴露面**。  
- **TLS**：由反向代理（Nginx、Caddy、云负载均衡）终止证书；应用层可只监听内网或本机 + 反代。  
- **鉴权（MVP 必做）**：至少 **单用户口令 / HTTP Bearer Token / 预共享 API Key**（择一实现简单方案）；不在 URL 里传密钥。后续可换登录体系。  
- **限流**：按 IP 或按 Token 做 QPS/每日上限，防止刷爆模型账单与向量库。  
- **Headers**：`HSTS`（生产）、收紧 `CORS`（仅你的前端源或同源）。

### 2.2 隐私与数据流

- 简历与 JD 属敏感信息：**应用日志默认不落用户问题全文**（可配置采样/截断）；调试模式显式开启且勿开公网。  
- 调用 **第三方 LLM/Embedding** 时，README 与页面显著位置说明 **数据出境/留存以各厂商条款为准**；敏感经历可维护 **脱敏版** `RESUME_FACTS.md`。  
- **密钥**：仅环境变量或密钥管理服务注入；**禁止**提交进 Git。多厂商 = 多组 Key，未启用的厂商可不配置。  
- **多租户**：仍不展开；公网单用户场景下通过 **强鉴权** 等价于单租户。

## 3. 功能范围

### 3.1 MVP（必选）

| ID | 功能 | 说明 |
|----|------|------|
| M1 | 语料入库 | 扫描指定目录下的 `.md`，解析 front matter（可选）、按标题递归切块、建索引版本号 |
| M2 | 简历问答 | 用户提问 → **RAG 检索** → LLM **仅依据上下文** 作答，并返回 **引用列表**（文档名 + 摘录） |
| M3 | 拒答策略 | 检索分数低于阈值或上下文为空时，固定模板拒答，**不调生成**或可短答 |
| M4 | 简易 Web UI | 输入问题、展示回答与引用；可选「展示检索到的片段」调试开关 |

### 3.2 v1（与转型计划对齐，紧随 MVP）

| ID | 功能 | 说明 |
|----|------|------|
| V1 | JD 对照 | 用户粘贴 JD 全文 → **关键词/BM25 粗匹配 + LLM 归纳**：匹配点 / 缺口 / 建议话术要点 |
| V2 | 面试题生成 | 基于入库简历文本或指定段落，生成 **针对性面试题清单**（可带参考答案提纲） |
| V3 | 多轮会话 | **滑动窗口摘要**或「每轮单独 RAG」二选一（实现阶段定） |

### 3.3 明确不做（本阶段）

- **自动替你改简历成稿**（易产生事实编造）；改为「对标 JD 的差距点」再由人改。  
- **简历 PDF 上传与解析**：首版 **不做**；经历事实仅通过 **`profile/RESUME_FACTS.md`** 维护（见 §4.2）。  
- **多模态看图**：不在 MVP；若以后要接 PDF/VLM，在 v2+ 单列方案。

## 4. 语料模型

### 4.1 内置知识库（来自 FindAIJob 仓库）

- `大模型与多模态面试笔记_定稿.md`（若放在仓库根目录则一并索引）  
- `docs/RAG系统设计_定稿.md`  
- `docs/多模态应用方案_定稿.md`  

### 4.2 简历事实源（已定稿：RESUME_FACTS.md）

- **路径约定**：`profile/RESUME_FACTS.md`（Git 可 ignore 或提交脱敏版；公网部署时勿提交含隐私的实稿）。  
- **内容**：只写 **可对外陈述** 的经历事实（公司可匿名、数据可区间化），供 RAG 引用；**禁止**让模型在缺乏 chunk 时补全经历。  
- **元数据**：`doc_type=resume`，与 `study` 类笔记区分，便于按问题类型过滤或加权。

### 4.3 切块与元数据（对齐 RAG 定稿 §4）

- **递归切分**：`#` 标题边界优先，其次段落，控制 `chunk_size` / `overlap`。  
- **元数据**：`doc_id`、`chunk_id`、`source_path`、`heading_path`、`doc_type ∈ {study, resume, jd_session}`。

## 5. 总体架构

```
┌─────────────┐     ┌──────────────────┐     ┌─────────────┐
│   Web UI    │────►│   API Gateway    │────►│  RAG Orchestrator │
└─────────────┘     └────────┬─────────┘     └──────┬──────┘
                             │                       │
                             │              ┌────────┴────────┐
                             │              ▼                 ▼
                             │       ┌────────────┐   ┌────────────┐
                             │       │ Retriever │   │  Generator  │
                             │       │Hybrid可选  │   │ LLM + 模板  │
                             │       └─────┬──────┘   └─────────────┘
                             │             │
                             ▼             ▼
                     ┌─────────────┐   ┌─────────────┐
                     │ Index Store │   │ Embed Model │
                     │向量+稀疏可选 │   │ 本地或 API │
                     └─────────────┘   └─────────────┘

离线索引：MD 变动 → ingest job → chunk → embed → upsert → version bump
```

- **Retriever**：MVP 可 **纯向量**；若中文专有名词召回弱，再上 **BM25 混合 + RRF**（见《RAG 系统设计》§5.3、§6）。  
- **Rerank**：MVP 可跳过；v1 对 JD 长文本可考虑 **cross-encoder 或 LLM 重排** Top-k。

## 6. 核心流程说明

### 6.1 简历 / 笔记问答

1. Query → Embedding → Top-k chunk（可加 `doc_type` 过滤：仅简历 / 含全部）。  
2. 组装上下文：`[CONTEXT id=… source=…]\n...\n[/CONTEXT]`。  
3. 系统指令：**仅引用上下文；无依据则拒答；回答末列出引用 id**。  
4. 可选：阈值以下 **不调用 LLM**，直接返回「知识库未命中」。  

### 6.2 JD 对照（v1）

1. JD 切块或整段存入 **临时会话索引**（或内存），或与主库共用 `doc_type=jd`。  
2. **双路**：BM25 找硬技能词命中 + 向量找语义相关段落。  
3. LLM 输出结构化：**匹配要点 / 风险缺口 / STAR 话术建议**，并声明「基于你提供的 RESUME_FACTS」。  

### 6.3 面试题生成（v1）

1. 检索与岗位或用户选的「主攻方向」最相关的简历 chunk + 笔记 chunk。  
2. LLM 生成 **问题列表 + 考察点**，可选「参考答案提纲」仅限「材料中有的经历」。

## 7. 实现路径对比与推荐

| 方案 | 描述 | 优点 | 代价 |
|------|------|------|------|
| **A. 极简 Python Monolith（推荐 MVP）** | Flask/FastAPI + 单进程向量库 + **可插拔 LLM/Embed 提供商** | 迭代快、易加鉴权与限流、适合公网单机 + 反代 | 弹性与多实例需后续补 |
| **B. LlamaIndex / LangChain 编排** | 框架封装 RAG pipeline | 开发快 | 依赖重；多厂商仍要自包一层配置 |
| **C. Serverless / 纯前端向量** | WASM 或小函数 | 省服务器 | MVP 密钥与调试不宜，公网更不推荐首选用 |

**推荐**：**方案 A**；对外 **LLM / Embedding 一律走统一接口**，见 §8.1。

## 8. 技术选型与多厂商切换（已定稿）

### 8.1 抽象要求

- **LLMProvider**：`chat(messages, **opts) -> stream|str`；支持至少两种实现（如 **OpenAI 兼容 API**、**DashScope 通义**）。  
- **EmbeddingProvider**：`embed(texts: list[str]) -> list[list[float]]`；维度与向量库字段一致；换厂商需 **重建索引** 或在库中记录 `embedding_model_id` 防混用。  
- **配置**：环境变量或 `config.yaml`（勿入库）示意：  
  - `LLM_PROVIDER=openai|dashscope|ollama|...`  
  - `EMBED_PROVIDER=...`  
  - 各厂商独立 Key/BaseURL/Model 名（如 `OPENAI_API_KEY`、`DASHSCOPE_API_KEY`、`OLLAMA_HOST`）。  
- **语义**：切换 provider 属于 **运维操作**；README 写明「切换后请重新 ingest」若 embedding 变更。

### 8.2 组件选型（实现阶段落地）

| 层级 | MVP 建议 | 备注 |
|------|----------|------|
| 运行时 | Python 3.11+ | — |
| Web | FastAPI + 同源静态页 或 Jinja 单页 | 前置 HTTPS 由反代负责 |
| 向量库 | Chroma 持久化卷 或 sqlite-vss | 公网实例数据盘需备份 |
| 稀疏检索 | rank_bm25（v0.5） | JD/技能词召回增强 |
| 进程与部署 | **Dockerfile + 示例 compose**（含反代占位） | 满足公网交付习惯 |

## 9. 评测与验收（MVP）

- **小型黄金集**：10～20 条问题，含「笔记中有答案 / 应拒答 / 跨文档综合」三类。  
- **指标**：人工看 **引用是否正确**、**是否胡编**；检索 **Recall@5** 可做粗测。  
- **回归**：改 prompt 或切块策略后跑同一批问题。

## 10. 风险与对策

| 风险 | 对策 |
|------|------|
| 幻觉编造经历 | 经历类问题 **强依赖 RESUME_FACTS** chunk；系统提示禁止补全未出现项目 |
| 泄露隐私 / 盗刷 | **鉴权 + 限流 + HTTPS**；日志脱敏；监控异常 QPS |
| 公网扫描与攻击 | 非必要端口不关；关闭调试接口；依赖及时更新 |
| 切块切断表格/列表 | Markdown 列表尽量与父标题同 chunk；调 overlap |
| 成本 | 空检索短路；缓存 query embedding；JD 长文分段（v1） |
