# 多模态应用方案（定稿）

| 项 | 说明 |
|----|------|
| 文档目的 | 定义一类 **图像/视频 + 文本** 的 AI 应用如何从场景落地到架构、数据、评测与运维，便于方案评审、面试陈述或与 RAG 文档配套使用 |
| 适用范围 | 看图问答、文档/票据理解、审核与风控辅助、客服截图分析、工业/巡检辅助、营销素材理解等 **强视觉输入** 场景 |

---

## 1. 背景与建设目标

### 1.1 多模态应用在解决什么问题

- **输入天然多源**：用户上传照片、截图、图纸、表格、视频帧；纯文本 LLM 无法直接消费。  
- **任务形态**：不仅是「描述图里有什么」，还包括 **OCR、定位、对比、推理、按规范输出结构化结果**。  
- **与纯 CV 的差别**：传统 CV 多输出框/掩码/类别；多模态应用往往要 **自然语言交互、开放词表、业务流程对接**（与《大模型与多模态面试笔记》中 VLM 定位一致）。  

### 1.2 建设目标（可写入 OKR）

| 维度 | 说明 |
|------|------|
| 业务可用 | 在约定场景下 **任务成功率 / 抽检通过率** 达标 |
| 体验 | **首 token、端到端 P99** 可接受；弱网/大图有策略 |
| 可控 | **幻觉、越权、敏感内容** 有检测与人工兜底路径 |
| 成本 | **GPU 与 API 调用** 可归因、可预算、可降级 |

---

## 2. 能力边界与术语

- **VLM（视觉语言模型）**：输入图像（+可选文本），输出文本或结构化结果（含部分模型的 **Grounding**，即框/坐标）。  
- **对齐模块**：Vision Encoder → **Adapter / Q-Former / Projector** → LLM token 空间（如 LLaVA、Qwen-VL 范式）。  
- **工具增强**：检测/分割/OCR/搜索 等 **不由单一 VLM 包打天下**，而是由 Agent 编排。  
- **多模态 RAG**：以 **CLIP 图文向量** 或 **多模态 embedding** 建库，检索相关图像/切片再交给 VLM 或 LLM（与《RAG 系统设计》可组合）。  

---

## 3. 场景与路线选型

### 3.1 场景 — 技术路线初判

| 场景特征 | 倾向路线 | 备注 |
|----------|----------|------|
| 截图/票据/表格，强依赖字 | **OCR + LLM** 或 **强 OCR 的 VLM** | 小字、密集表需专项评测 |
| 开放聊天式「看图说两句」 | **通用 VLM** | 先控输入分辨率与成本 |
| 要数清、要比对细微差异 | **专用 CV + 规则/表格** 为主，VLM 为辅 | 避免单模型硬扛计数 |
| 要用自然语言找物体再分割 | **Grounding DINO + SAM**（+ VLM 解释） | 定位与像素级分开 |
| 海量图库语义搜索 | **CLIP/多模态向量** + 倒排/ANN | 与文本 RAG 类似建索引 |
| 视频理解 | **抽帧 + VLM** 或 **视频多模态模型** | 时序一致性与成本需单独设计 |

### 3.2 三种主流范式（可混用）

**A. 端到端 VLM**  
- 结构简单、迭代快；短板是 **幻觉、细粒度、长图**。  
- 适合：对话式理解、说明类输出、中等精度 OCR 类。  

**B. 工具增强（VLM / LLM + Tools）**  
- 检测、分割、OCR、网页抓取、计算器、向量库等为 **Tools**；核心模型做规划与汇总。  
- 适合：**高可靠字段抽取**、要落库的结构化工单、已知失败模式可工具兜底的场景。  

**C. 混合**  
- 简单子任务走工具，开放式解释走 VLM；或 **前半段结构化、后半段生成摘要**。

## 4. 参考架构

### 4.1 逻辑视图

```
客户端（图/视频/文本）
        │
        ▼
┌───────────────┐     ┌─────────────────────────────┐
│ 接入与预处理  │ ──► │ 安全：鉴权 / 杀毒 / 内容风控  │
│ 压缩/裁切/去敏│     └─────────────────────────────┘
└───────┬───────┘
        │
   ┌────┴────┐
   ▼         ▼
工具链      VLM 服务
 OCR       （同步或流式）
 检测       
 Grounding   
 向量检索    
   │
   └────┬─────┘
        ▼
┌───────────────────┐
│ 会话 / Agent 编排  │（可选：多步、人机确认）
└─────────┬─────────┘
          ▼
┌───────────────────┐
│ 结构化输出 / 工单  │
│ 审计日志与引用片段  │
└───────────────────┘
```

### 4.2 与 RAG 联合

- **文本知识**：按《RAG 系统设计》做 chunk 检索。  
- **图像知识**：图像或 **patch** 嵌入向量库；query 可为 **图文** 或多模态 query。  
- **融合 prompt**：检索到的 **文本片段 + 图像（或-caption）** 一并作为条件；注意 **总长与位置 bias**。

## 5. 模型与组件选型要点

### 5.1 选型维度（面试/评审可逐项说）

| 维度 | 关注点 |
|------|--------|
| 语言与市场 | 中文、行业术语；是否需 **本地化部署** |
| OCR / 图表 | 菜单、票据、截图、柱状图等不同子类要 **单独压测** |
| Grounding | 是否需要框/点多模输出；选型 **带定位能力的 VLM** 或外挂检测 |
| 延迟 | **分辨率、帧数、并发**；是否接受异步任务 |
| 许可证与数据 | **商用条款、日志是否用于训练** |
| 成本 | Token、GPU 时长、向量与存储 |

### 5.2 常见组合（命名仅作占位）

- **通用对话 + 中文 OCR**：偏重 **开源/国产 VLM 系列**（按你的部署条件替换具体型号）。  
- **先要框再抠图**：**开放词汇检测** + **SAM 类分割**；分类名由业务词表约束。  
- **只要嵌入、不要长文本**：**CLIP 类** 双塔索引 + 轻量后端。  

### 5.3 不推荐的做法（方案里要主动规避）

- 用单一 VLM 承担 **高精度计量、法务级数字、安全关键告警** 而不做校验。  
- 无分辨率上限地接受用户图，导致 **OOM 与账单元爆炸**。  
- 无 **租户隔离** 的多用户图库共索引。

## 6. 数据与迭代

### 6.1 数据类型

| 类型 | 用途 |
|------|------|
| 图文指令对 | SFT：**问题—回答** / **输出 JSON schema** |
| Grounding 标注 | 文本短语 ↔ 框，用于定位能力 |
| 难例回流 | **线上误判**、用户修正，进入迭代集 |

### 6.2 迭代策略（由浅入深）

1. **Prompt 与输出 schema 固化**：先对齐格式，再谈效果。  
2. **检索增强**：业务知识、商品库、SOP **进 RAG**。  
3. **工具链接**：固定字段用 OCR/表格解析 **硬抽出**，VLM **只做校验或摘要**。  
4. **轻量微调**：LoRA / Adapter，优先 **结构化输出一致性** 与 **领域话术**。  

### 6.3 和多模态 RAG 的文档策略

- 图像侧：除 embedding 外，建议存 **可读 caption、OCR 全文、版面结构**（便于稀疏检索与人的审计）。  

---

## 7. 评测体系

### 7.1 分层

| 层 | 指标示例 |
|----|----------|
| 感知 | OCR 字级准确率、检测 mAP（若用检测） |
| 理解 | 字段级 F1、与标准答案的一致性（结构化任务） |
| 生成忠实度 | 输出是否可被 **图中证据或 OCR 文本** 支持 |
| 安全 | **拒答是否合理**；敏感类目误放行率 |
| 系统 | P99、单次成本、大图失败率 |

### 7.2 离线集构造

- **分层抽样**：清晰度、语种、类目、室内外、日夜间（按业务）。  
- **对抗项**：遮挡、翻拍、水印、拼图、语义相近易混类别。  

### 7.3 上线门禁

- 与《RAG 系统设计》同理：**模型版本 + prompt + 工具链** 变更走回归集；**核心指标熔断**。  

---

## 8. 工程与非功能

### 8.1 预处理规范

- **最大边分辨率**、JPEG 质量、RGBA 处理、EXIF 方向矫正。  
- **视频**：关键帧间隔、最长时长、音视频分离策略（若只管画面）。  

### 8.2 性能与成本

- **异步队列**：大图/批量视频走任务型 API + 回调。  
- **缓存**：同图重复问法可缓存 **embedding 或 VLM 中间特征**（注意隐私 TTL）。  
- **降级**：VLM 不可用时降级为「仅 OCR + 文本模型」等有损路径并在产品侧提示。  

### 8.3 观测

- Trace：**输入指纹（hash）→ 选用的工具/VLM → 置信度字段 → 输出**  
- Bad case：**幻觉类 / OCR 漏检 / grounding 跑偏** 分类打标回流  

---

## 9. 安全与合规

- **租户与对象存储 ACL** 对齐；不落无关用户图。  
- **人脸识别、未成年人、医疗影像** 等按法规做 **分级策略与审计**。  
- **Prompt Injection**：多模态下图片可藏对抗文本——需 **前置过滤与用户教育**（产品策略与模型输入清洗结合）。

## 10. 分阶段路线图（示例）

| 阶段 | 交付 |
|------|------|
| MVP | 单路 VLM、固定输出 schema、基础评测与安全拦截 |
| v1 | 工具增强（OCR/检测必选一路）、预处理规范、异步大任务 |
| v1.5 | 多模态 RAG、Agent 编排、人工审核工作台 |
| v2 | 领域微调与健康度看板、A/B 与成本归因自动化 |

## 11. 面试口述版（约 90 秒）

「多模态应用我会先看 **场景要的是交互还是精确字段**。偏交互就用 **VLM**，但关键数字和结构化字段最好用 **OCR 或检测** 做成 **工具链路**，模型负责规划和校对，这比单一 VLM 稳。要用自然语言抠物体就用 **检测接分割**，再按需接语言模型总结。工程和 RAG 一样要 **预处理、租户隔离、Trace、评测分层**——多了一个 **幻觉与 OCR 链路** 的维度。大图视频要 **异步和分辨率预算**，上线用 **离线集加对抗样本** 做门禁，核心业务要有 **降级和人审出口**。」
